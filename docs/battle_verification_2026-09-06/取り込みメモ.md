# 独立検証（2026-09-06）の修正候補 取り込みメモ

`manatobi_verified_candidates_2026-09-06.zip` の `candidate/` と `fix-candidates.patch` は
対象コミット `dec75f03`（別系統：playStyle 早押し／じっくり版）を基準にしており、
本リポジトリの現行コードには `git apply` できなかった。
そのため **4つの修正内容を現行コードへ手で移植**した。

| # | 検証で見つかった問題 | 現行コードへの移植先 |
|---|---|---|
| 1 | 待機中に退出しても部屋が閉じず、合言葉で入れてしまう | `battle.ts abortRoom()` をトランザクション化。waiting なら `status: 'aborted'` も書く。`firestore.rules` の (D) 離脱枝で waiting→aborted を許可（left を書く更新に限る）。left は waiting/playing のときだけ書ける |
| 2 | 対戦中の明示的退出で早期決着しない | `useBattleRoom.ts` に `firstLeaver / explicitForfeit`。left が付いた時点で `finished`、退出者は得点に関係なく負け。試合中の「対戦をやめる」ボタンと、画面を離れたとき（unmount / pagehide）の退出記録を追加 |
| 3 | 2人が同時に全国待機すると両方が待ち続ける | `battle.ts findOrEnqueue()` を「先に待機票を置く → 探す → 双方の票を同一トランザクションで確認・削除 → 部屋作成」に変更 |
| 4 | 結果を再読み込みすると再申告して未処理エラー | `useBattleRoom.ts` の申告 effect で `room.attest[uid]` があれば再送しない。送信失敗は `setError` に流す |

候補に含まれていた `playStyle`（早押し／じっくり）は本リポジトリには存在しないため取り込んでいない。

## 追加したルールテスト（tests/battle.exploit.test.ts）
- 待機中の退出は status: aborted と同時に書ける（正常系）
- 待機中に left を書かず status だけ finished にはできない
- 決着後（finished）に left を書けない

`npx firebase emulators:exec --only firestore --project mntb-rules-test "npx vitest run tests/battle.exploit.test.ts tests/battle.rules.test.ts"` → 166 件合格。

## 本番反映時の注意
`firestore.rules` を変更しているので、フロントの公開と同時に Firebase Console → Firestore → ルール へ反映すること。
