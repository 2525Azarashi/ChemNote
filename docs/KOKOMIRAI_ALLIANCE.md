## 0. 先に結論（3行）

1. **ここみらいは「インプット（講義＋テキスト）」の会社で、アウトプット（演習・採点・弱点分析）を自社で持っていない。** しかも彼ら自身が「本書で基礎を掴んでから、問題集や過去問を解いて知識の穴を埋めていけばOK」と公言している。**その「問題集・過去問」の位置がマナトビの空席**。
2. **彼らは講義配信を自社アプリ「ココミラ」で握っている。** だからマナトビは絶対に「講義を配信する側」に回ってはいけない。**ココミラへ送客する演習レイヤー**として入るのが唯一の正解。
3. **交渉のカギは「向こうの売上が増える」こと。** ここみらいの収益はテキスト販売・参考書印税・ここサポ。マナトビが単元ごとにテキスト／参考書への導線を持てば、**マナトビは彼らの販売チャネルになる**。工数はこちらが全部持つ。

### 1-2. 出発点＝反・予備校

公式サイトの説明文が、この会社の意思決定を全部説明している。

> 代表のシュンスケが受験生時代某有名塾にぼったくられた恨みから始まったチャンネル。
> 塾に通わずとも受験を戦えるように、高校生に向けて、教科書レベルを網羅的にカバーした体系的な講義動画を中心にアップしている。

さらに「教育業界への怒りと若気の至りにより勢いで始めた」とも書いている。

**ここから読める意思決定のクセ：**
- 「金銭的負荷を受験生にかけない」ことが企業理念レベルの制約。→ **高額課金・生徒からの追加徴収を伴う提案は通らない。**

- 逆に「受験生が得をする」「独学者が救われる」ロジックには極端に強く反応する。→ **提案の主語を「受験生」にすべき。**


**詳細：**

- **テキスト有料化は2023年10月1日**。それまで4年間無料公開していた。本人の投稿：「4年間無料で公開し続けていたので、『有料化する』などと言ったらものすごく文句を…」→ **課金には慎重で、ユーザーの反発を非常に気にする。**

- テキストは**穴埋め式**で、講義はテキスト前提。本人の言葉：「**そもそも僕たちの授業はテキストを持っていることを前提にしています。テキストに書いているからと、黒板に書かないことも多いです。**」

### 2-2. 実装案（優先度順）

> この「ココミラ優先」設計を提案書に明記すること自体が、最大の信頼獲得材料になる。

#### ★B. つまずき→講義の自動誘導（マナトビ固有の価値）

マナトビは**どの単元で何問間違えたか**を持っている。だから
「c4_2 物質量 を3問連続で間違えた」→「**molの講義をもう一度**」と自動で出せる。

**ここみらいがYouTubeやココミラだけでは絶対に得られない導線。** そして彼らの「mol計算はみんな大嫌い」という認識と完全に噛み合う。

#### ★C. テキスト／参考書への送客（＝相手の売上に直結）

- 単元ページに「この範囲を書き込みで固める → **ここみらい 化学基礎テキスト**」リンク
- リンクは**素の販売ページ**（kokomirai.jp / 学研モール / Amazon）。**アフィリエイト報酬はこちらは取らない**＝売上は100%先方。
- まとめプリント（印刷版）のフッターに「講義：ここみらいチャンネル／テキスト：kokomirai.jp」のクレジットを入れる。**紙で家庭に残る接触面**が増える。

#### ★D. 誤答データ・出題傾向のフィードバック（無償提供）

シュンスケ氏はテキスト制作に「何ヶ月も」かけ、「何十冊もの参考書と睨み合いながら構成を練り」と書く人。**データは効く。**

提供できるもの：
- 単元別の誤答率ランキング（＝どの講義を補強すべきか）
- 共通テスト11年の出題頻度・形式変化（例：2022年から「小問集合＋テーマ型総合問題」の二層構造に固定化）
- 「テキストのこの説明の後に、この誤答が減った」レベルの効果測定

→ **次のテキスト改訂・講義リメイク・次の参考書企画の一次資料になる。**

#### ★E. 横展開：学研ムビスタ本の「STEP4」になる

ムビスタ本の構成は STEP1 講義 → STEP2 要点整理 → **STEP3 基本練習**。
そして本人が「9割以上なら**問題集・過去問**へ」と言っている。

→ **マナトビの演習エンジンを 公共・政治経済 に横展開して「STEP4 実戦演習」を無料Web提供**する。
- 学研本の購入者特典にできる（＝**書籍の付加価値＝販売部数**）
- 出版社側にとっても「紙＋動画＋Webドリル」は新しい売り方
- **シリーズ第2弾以降の企画材料**になる

> ここまで来ると、これは「コラボのお願い」ではなく「あなたの本の売上を増やす提案」になる。それが返信率を決める。

#### F. 相互送客

- マナトビ側：トップ／単元／まとめプリントに ここみらい・ココミラ・参考書 を常設掲出
- ここみらい側：無理のない範囲で（概要欄1行、または動画内で「演習はこれ使って」と一言）
- **先に我々が出す。見返りは後で相談、が正しい順序。**

### 2-4. 実証実験の進め方（相手が「YES」と言いやすい最小単位）

```
             計測：講義への遷移数／ココミラ導線のCTR／テキストページ流入

Phase 3  ── 良ければ 生物基礎・公共・政治経済 へ横展開
```

## 5. 実装側の準備（先方の返信が来る前にやれること）

返信が来てから作り始めると失速するので、**許諾前提の部分だけ先に作る**。

1. **単元→講義 の対応表を空で用意**（`src/data/kokomiraiLectureMap.ts` のような形）
   - 29単元分のキーだけ作り、URLは空文字。許諾が来たら埋めるだけの状態にする
2. **「講義へ戻る」ボタンのUIコンポーネントを作る**
   - `対応URLが未設定なら非表示`にしておけば、許諾前でも本番にマージできる
3. **ココミラのディープリンク仕様を調査**
   - iOS/Android のスキーム、未インストール時のストアフォールバック
4. **誤答率レポートの出力スクリプト**
   - 先方に渡す「単元別の誤答率」を出す形を先に作っておくと、Phase 2 の報告が速い
5. **デモ環境を1つ固定**
   - メールに貼るURLは、いつ見ても動く状態を保つ
