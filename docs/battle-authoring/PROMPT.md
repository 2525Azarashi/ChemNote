
**この枠に書かれた章IDが、あなたの仕事の全部である。**

## 1. まず結論から

あなたの仕事は
**担当範囲の演習問題を読んで、対戦で1画面で解ける小問に作り直すこと** である。

- 問題を **切り捨てない**。読んで、割って、作り直す。
- 成果物は **JSON のテキストだけ**。
- 渡し方は **チャットにそのまま貼って返すだけ**。
- **1問1問ていねいに。時間は無制限。数より質。**

### ★★やってはいけないこと（これを破ると全部が壊れる）★★

| やること | ★やらないこと★ |
|---|---|
| 元データを読む | `git add` / `git commit` / `git push` |
| JSON を書く | PR を作る・更新する |
| `npm run verify:authored` でエラー0にする | ZIP を作る（`pack:authored` は使わない） |
| **JSON をチャットに貼って返す** | 生成ファイル（`pool.*.generated.ts` / `battlePool.ts`）を編集する |
| | 既存の問題データ（`src/data/**`）を編集する |
| | 担当範囲の外の章に手を出す |

**なぜ git を触らないのか。**
教科・範囲ごとに **複数の作業場が同時に動いている**。それぞれが push すると、
同じ生成ファイルを同時に書き換えて **後からマージしたほうが先のものを消す**。
だから **取り込みとファイルへの格納は本体が1か所でまとめてやる**。
あなたは **書いて、検証を通して、チャットで返す**。それだけ。

## 2. 手順

### 手順0 — 配管の入ったブランチに移る（読むだけ）

作問に使うコマンド（`export:chapter` / `verify:authored`）は
`genspark_ai_developer` ブランチにしか入っていない。

```bash
git fetch origin genspark_ai_developer
git checkout genspark_ai_developer
npm ci        # 初回だけ
```

★ここから先、`git` は二度と使わない。★ checkout 以外は禁止。

### 手順1 — 担当章の元データを丸ごと書き出す

担当章を **1つずつ** 書き出す。

```bash
npm run export:chapter -- <教科ID> <章ID>
# 例: npm run export:chapter -- chemistry_basic c1_2_A
# → build/chapter-source/chemistry_basic/c1_2_A.md ができる
```

このファイルには、その章の
**大問のリード文・全小問・正解・選択肢・解説・補足** が **1文字も省略せずに** 入っている
（章によっては 150KB 前後になる）。

★**全部読む。**★ 要約された何かを読んで書いてはいけない。
**あなたが作る誤答の材料は、この解説の中にしか無い。**

各小問には印がついている。

```
#### [対戦済] `q1_x`          ← すでに対戦に出ている。触らない
#### [★要作成 — 理由] `q2_1`  ← ★これがあなたの作業対象★
```

ファイルの末尾に「作成対象の小問一覧（コピー用）」がある。

### 手順2 — 1問ずつ作り直す

作業対象の小問を、**上から順に1つずつ** やる。まとめて機械的にやらない。

各小問について、次の4つを自問する。

1. **この小問は、元の大問の何を聞いているのか？**
2. **その内容を、リード文なしで、1画面だけで聞ける形にできるか？**
3. **できるなら、どの形式（`choice4` / `choice` / `kana`）が自然か？**
4. **誤答は、解説のどこに書かれているつまずきから取れるか？**

**4 が書けないなら、その問題は作らない。書けない誤答を置くのが一番の失敗である。**

### 手順3 — 章ごとに1ファイルの JSON に書く

置き場所は **`src/battle/data/authored/<教科ID>.<章ID>.json`**。
（このパスは検証を走らせるためだけに使う。**コミットはしない。**）

```
src/battle/data/authored/chemistry_basic.c1_2_A.json
src/battle/data/authored/chemistry_basic.c1_2_B.json
   …担当章のぶんだけ
```

★1ファイル＝1章。複数の章を1ファイルに混ぜない。★

### 手順4 — 自分で検証して、エラー0になるまで直す

```bash
npm run verify:authored -- <教科ID>
# 1ファイルだけ見たいとき:
npm run verify:authored -- --file src/battle/data/authored/chemistry_basic.c1_2_A.json
```

**エラーが1件でもある JSON は返してはいけない。** 出たエラーは全部あなたが直す。
警告（warn）は止まらないが、**全部読んで内容がずれていないか自分で判断する**。

### 手順5 — ★チャットに貼って返す★（§6 のテンプレどおりに）

1章ぶん書き終わって検証がエラー0になったら、**その章を待たずにすぐ返す**。
全章まとめて最後に返さない。**途中で切れたら全部が消えるから。**

## 3. JSON の書き方

### ファイル全体

```json
{
  "subject": "chemistry_basic",
  "chapterId": "c1_2_A",
  "authoredBy": "room-cb-1",
  "questions": [ ... ]
}
```

`authoredBy` は §0 の【作業場の名前】をそのまま書く。

### 1問の形（選択式）

```json
{
  "id": "a:c1_2_A:q2:q2_1:1",
  "source": { "chapterId": "c1_2_A", "problemId": "q2", "subQuestionId": "q2_1" },
  "format": "choice",
  "prompt": "空気は、混合物・単体・化合物のどれに分類されるか。",
  "label": "",
  "options": [
    { "text": "混合物", "correct": true,
      "why": "空気は窒素・酸素・アルゴンなどが混ざったもの。元データのひっかけ欄に『牛乳・空気・石油は純物質に見える』という見た目の罠が挙げられている。" },
    { "text": "単体",
      "why": "単体は1種類の元素だけからなる純物質。空気は複数の物質の混合なので純物質ではない。" },
    { "text": "化合物",
      "why": "化合物は決まった割合で元素が結合したもの。空気の組成は場所や高度で変わるので化合物ではない。" }
  ],
  "oneLine": "混合物。均一に見えても窒素と酸素などが混ざっているだけで、結合はしていない。",
  "timeLimit": 12
}
```

### 1問の形（かな入力）

```json
{
  "id": "a:c1_1:q4:q4_1:1",
  "source": { "chapterId": "c1_1", "problemId": "q4", "subQuestionId": "q4_1" },
  "format": "kana",
  "prompt": "水と混ぜて加熱すると沸点が一定にならない混合物になる、消毒用アルコールの主成分である液体の名称をカタカナで答えよ。",
  "label": "",
  "answer": "エタノール",
  "answerWhy": "元の大問のリード文に『水とエタノールなどの加熱』とあり、水と混ぜた場合が混合物として扱われている。",
  "oneLine": "エタノール。純物質は沸点が一定だが、水と混ぜた混合物では沸点が一定にならない。",
  "timeLimit": 16,
  "grounding": "水とエタノールの混合物のグラフ"
}
```

### 各フィールドの決まり（★検証器の実装そのまま★）

| フィールド | 決まり | 違反したら |
|---|---|---|
| `id` | `a:<章ID>:<大問ID>:<小問ID>:<連番>`。`a:` で始まる。同じ小問から複数作るなら連番を 1,2,3… | error |
| `source` | 元データに **実在する** 章/大問/小問の3つ全部。`chapterId` はファイルの章と一致 | error |
| `format` | `choice4`（**ちょうど4択**）/ `choice`（2〜6択・**ただし4個なら choice4 にする**）/ `kana` | error |
| `prompt` | **150文字以内**。これ単体で答えが決まること。`prompt` と `label` が両方空は不可 | error |
| `label` | 補助の見出し。不要なら `""` | — |
| `options` | 選択式のみ。**2〜6個**。`correct: true` が **ちょうど1つ** | error |
| `options[].why` | **全選択肢に必須**。trim して **4文字以上** | error |
| `answer` | kana のみ。**カタカナ＋長音「ー」だけ／2〜8文字**。`options` は書かない | error |
| `answerWhy` | kana のみ。**必須** | error |
| `oneLine` | **必須。10〜120文字**。試合後に出す1行の解答 | error |
| `timeLimit` | **8〜30（整数・秒）**。★範囲外は丸めずエラーになる★ | error |
| `grounding` | 正解が元データに直接見つからないとき **必須**。元データから **一字一句そのまま** 引用 | error |

### 選択肢どうしの禁止事項（機械的に検出される）

- **重複**: 空白・句読点・大文字小文字を無視して同じ → error
- **包含関係**: 任意の2つで `A が B を含む` または `B が A を含む` → **error**
  - ✗ `2種類` と `2種類以上` / ✗ `単体` と `単体・化合物` / ✗ `酸性` と `弱酸性` / ✗ `物質` と `純物質`
  - ✓ `単体` `化合物` `混合物`（互いに部分文字列でない）

### `prompt` / `label` に書いてはいけない語（14語・画面に存在しないものを指す）

```
上の文章 / 上の文 / 次の文章中 / 前問 / 上記の / 上図 / 下図 /
次の図 / 右の図 / 左の図 / 上の表 / 次の表 / 本文中 / 文章中の
```

### ★根拠の照合（`grounding`）— ここが一番つまずく★

検証器は **「正解の文字列が、その大問のどこかに実在するか」** を機械的に照合する。
照合先（haystack）は次を全部つないだもの。

```
その大問の本文 + 解説 + 解説の補足 + ★その大問の全小問の正解・許容解答★ + 図のキャプション
```

正解が見つからないと error になる。本当に正しいなら、
**`grounding` に元データから一字一句そのまま引用する**（`grounding` 自身も同じ照合を受ける）。

★実際に一番よく効く引用元は、解説の「解法の思考手順」の一文である。★
例:「純物質は1種類の粒子からなることを確認する」をそのまま `grounding` に入れる。
**自分の言葉に直したら通らない。コピペする。**

## 4. ★絶対に守るルール（過去に壊した原因）★

### ルール1 — 誤答を他の設問から借りてこない

★これが一番の失敗原因。★
過去のスクリプトは「同じ章の他の設問の答え」を機械的に持ってきて誤答にした。
結果、**誤答のほうが正しい問題** ができた。

誤答は次のどれかからだけ取る。

- 解説の `stumblingPoints`（つまずきポイント）
- 解法の思考手順にある「〜を誤答として排除する」という記述
- 「💡 ココが狙われる」欄の **ひっかけ** の記述
- その概念の定義から論理的に導ける、**明確に誤った理解**

**その誤答が「なぜ誤りか」を `why` に書けないなら、その誤答は使ってはいけない。**

### ルール2 — リード文を切らない（1画面で解けるようにする）

対戦画面には **`prompt` と `label` しか出ない。** リード文は出ない。
必要な情報は `prompt` の中に **全部書き切る**。

- ✗ 悪い: `文章中の( ア )に入る語句を答えよ。`
- ✓ 良い: `1種類の粒子だけからできていて、融点や沸点が採取場所によらず一定である物質を何というか。`

**聞いている内容は元の小問とまったく同じ。言い方だけを1画面用に直す。**

### ルール3 — 表記ゆれが起きる答えを kana にしない

kana は1文字ずつ照合する。1文字違えば不正解になる。

- ✓ `エタノール` `ナトリウム` `イオン`
- ✗ `化合物`（漢字）/ `えたのーる`（ひらがな）/ `H2O`（英数字）/ `割合（または組成）`（2通りある）

**漢字・数値・式が答えになるものは、必ず選択式にする。**
五十音パネルには打てない文字（「ヲ」など）がある。入っていると error。

### ルール4 — 選択肢を勝手に増やさない・減らさない

元データが **意図して2択にしている** ものを4択にすると、別の問題に化ける。

- ✗ 「元素／単体」の2択（この使い分けを問うのが目的）→ 4択にしない
- ✓ 「混合物／単体／化合物」の3択 → **分類の枠** なので同じ枠の語を足して4択にしてよい

**迷ったら増やさない。** 2択のまま出してよい。

### ルール5 — 図がないと解けない問題は作らない

対戦画面に図は出せるが **小さくて読めない**。

- 図の中身を `prompt` の文章に書き起こせるなら、書き起こして出す
- 書き起こせないなら **その設問は作らない**
- ただし、その大問のリード文が持っている知識を図なしで問えるなら、そちらを問題にしてよい

### ★ルール6 — 同じ内容を2か所で聞いていたら、片方を「なぜ」に変える★

元データでは、**別の大問が同じ物質・同じ判断を聞いている** ことがよくある。
そのまま両方作ると、**1試合で同じ問題が2回出る**。検証器はこれを検出できない。
**あなたが気づいて言い換える。**

実例（`chemistry_basic.c1_1` で実際にやったもの）:

| 内容 | 素のまま作った側 | ★言い換えた側★ |
|---|---|---|
| 酸素の分類 | `q2_2`「酸素は何に分類されるか」 | `p2_1`「酸素が **単体に分類される理由** はどれか」 |
| 空気の分類 | `q2_1`「空気は何に分類されるか」 | `p2_6`「空気が **混合物に分類される理由** はどれか」 |
| 水の電気分解→水素 | `q3_4`「単体か元素か」 | `p3_8`「**単体だと判断できる理由** はどれか」 |
| 空気の78%は窒素 | `q3_2`「単体か元素か」 | `p3_10`「**単体だと判断できる理由** はどれか」 |

「なぜ」に変えたほうの誤答も、**解説の思考手順から取る**（借りてこない）。

### ★ルール7 — 完答（複数選択）は「1つだけ選ばせる形」に割る★

元が「当てはまるものをすべて選べ（正解 ア・ウ・エ）」の場合、対戦では1つしか選べない。

- ✗ 4つのうち3つが正解 → 検証で `correct が1つでない` の error
- ✓ **裏返して1つに絞る**

実例（`c1_1` の `p4_ans`）:
元は「純物質の特徴をすべて選べ（ア・ウ・エ）」→
**「純物質には当てはまらず、混合物の特徴を述べているものはどれか」**（＝イを選ばせる）に変換。
**聞いている内容は同じまま、答えが1つになる。**

## 5. 検証エラーの読み方

```bash
npm run verify:authored -- <教科ID>
```

| メッセージ | 直し方 |
|---|---|
| `元データに存在しない小問を指している` | `source` の3つのIDを元データと突き合わせる。★出たら「元データを読まずに書いた」証拠★ |
| `id が重複している` | 同じ小問から複数作るなら末尾の連番を変える |
| `正解「〜」が元の大問の本文・解説・解答のどこにも見つからない` | `grounding` に元データから **一字一句そのまま** 引用する。引用できないなら根拠が無い＝作らない |
| `選択肢[n]「〜」に why が無い` | 根拠なく置いた誤答。理由を書けないなら別の誤答に変える |
| `選択肢「A」と「B」が包含関係にある` | 片方を別の語に差し替える |
| `「上の文章」は対戦画面に存在しないものを指している` | 必要な情報を `prompt` に書き切る |
| `kana の答えはカタカナ（＋長音）だけ` / `五十音パネルから打てない文字` | 選択式に変える／別の語にする |
| `oneLine は 10〜120文字` / `prompt は150文字以内` | 直す。短くできないなら分割が足りていない |
| `timeLimit は 8〜30` | 直す（丸めてはくれない） |
| `選択肢が4個なら format は choice4` | `format` を直す |

**警告（warn）は止まらない。** ただし全部読む。

```
元の小問の正解は「(イ)」だが、この問題の正解は「混合物」
```

これは **記号を語に戻した正常な警告**（`c1_1` では18件出て全部正常だった）。
一方、**聞いている内容がずれた場合にも同じ警告が出る**。自分で判断する。

## 6. ★返し方（このとおりに返す）★

### 6-1. 1章書き終わるごとに、すぐ返す

全章まとめない。**1章＝1回の返信**。

### 6-2. 返信の形（この見出しを必ず付ける）

````
=== AUTHORED / room-cb-1 / chemistry_basic / c1_2_A / 1 of 1 ===
問題数: 34（choice 30 / choice4 3 / kana 1）
verify: エラー0件 / 警告5件
警告の内容: すべて記号(イ)(ウ)を語に戻したことによるもの。内容のずれ無し。
作らなかった小問: q5_3（図が必須）, q7_1（記述で分割不能）

```json
{
  "subject": "chemistry_basic",
  "chapterId": "c1_2_A",
  "authoredBy": "room-cb-1",
  "questions": [ ... ]
}
```
=== END c1_2_A ===
````

### 6-3. 長くて1回で貼りきれないときだけ分割する

**JSON を途中で切って分けるのは最終手段。** まず「大問ごとに別の返信」にできないか考える。
どうしても分ける場合:

- 見出しを `… / c1_2_A / 1 of 3 ===` `2 of 3` `3 of 3` にする
- **`questions` 配列を分ける**（`{"subject":…,"questions":[ここだけ分割]}` を3つ作る）
- ★JSON の途中の文字列を切らない★ 本体が結合するので、**各パートがそれ自体で正しい JSON** であること

### 6-4. 全章終わったら、最後に1行で報告

```
=== DONE room-cb-1 / chemistry_basic 前半 ===
c1_2_A 34問 / c1_2_B 41問 / c1_3 22問 / c2_1 88問 / c2_2 30問 / c2_3 14問 / c2_4 25問
合計 254問。全ファイル verify エラー0。
```

**ファイルへの格納・コミット・PR は本体がやる。あなたは返すだけ。**

## 7. 合格した実例（★書き始める前に必ず読む★）

### 7-1. 本体が書いた完成品（51問・検証エラー0）

```bash
# 本体ブランチに入っている（ある場合）
src/battle/data/authored/chemistry_basic.c1_1.json
```

## 10. 質問への答え

**Q. 元データの問題文が間違っていると思う。直していいか？**
A. 直さない。`src/data/**` は触らない。気づいた点は §6 の返信に `気づいた点:` として1行で書く。

**Q. 同じ小問から10問作ってもいいか？**
A. よい。ただし **聞いている内容が本当に違う** 場合だけ。
言い方を変えただけの同じ問題を量産すると、対戦で同じ問題が続いて体験が悪くなる。

**Q. `descriptive`（記述式）はどうするか？**
A. 記述の答えの中に **選択式で聞ける核** があるなら作る。無ければ作らない。
例:「〜の理由を説明せよ」→「〜が起きる理由として正しいものはどれか」の4択にできる。

**Q. `sorting`（並べ替え）はどうするか？**
A. 「AとBではどちらが先か」の2択に割ると出せることが多い。
順序の根拠が解説にあるかを必ず確認する。

**Q. 計算問題はどうするか？**
A. 答えの数値を選択肢にする。誤答は **典型的な計算ミスの結果**（÷を×にした値、係数を掛け忘れた値など）。
解説の解法手順に、どこで間違えやすいかが書いてある。

**Q. 正解を何番目に置くか気にしたほうがいいか？**
A. **気にしなくてよい。正解を常に先頭に書いていい。**
本体が取り込むときに問題IDを種にして並べ替える。
`correct: true` は選択肢自身が持っているので、並べ替えても対応はずれない。

**Q. `timeLimit` を 40 秒にしたい**
A. **8〜30 の範囲外はエラー**（丸めてくれない）。
30秒で解き終わらない問題は1画面に載っていない可能性が高い。**先に2つに割ることを考える。**

**Q. 途中で会話が長くなって続けられなくなりそう**
A. だから **1章終わるごとに返す**（§6-1）。返した章は本体に届いているので、
やり直しになるのは書きかけの1章だけで済む。

**Q. 担当範囲の章が全部終わった。次は何をするか？**
A. **本体に §6-4 の完了報告を出して止まる。** 勝手に次の範囲を始めない。
