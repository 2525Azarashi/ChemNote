# 問題の作り方（追加・修正するとき）

`pool.joho.generated.ts` に問題を足す／直すときの決まりです。
**アプリが弾く条件**があるので、ここを守らないと該当問題が出題されなくなります。

---

## 1行の書き方

```ts
["j341", 3, 41, 1, 0, "次の問いに答えよ。",
 "DNCLで「x を 0 から 9 まで 1 ずつ増やしながら繰り返す」と書いたとき、繰り返しは何回実行されるか。",
 ["9回","10回","11回","無限"], 1, [0,1,2,3], 30, ""],
```

要素の意味は `はじめに読む.md` の「データ形式（タプル）」表を参照。

---

## 絶対に守る4つのルール（アプリのゲート）

| # | ルール | 破るとどうなる |
|---|---|---|
| 1 | `options` は **ちょうど4個** | その問題が読み込み時に除外される |
| 2 | `options` の4個は **すべて相異なる文字列** | 正解が2つある状態になり判定不能 |
| 3 | `answerIndex` は **0〜3** | 正解が存在せず、必ず不正解になる |
| 4 | `id` は **全450問（＋追加分）で一意** | 同じIDの問題が上書き・重複出題される |

### さらに守るべきこと

| 項目 | 制限 | 理由 |
|---|---|---|
| `label`（問題文） | **110字以内** | 超えると画面で末尾が `…` に切られ、問題が読めなくなる |
| `chapterId` | 1〜5のいずれか | 章の対応表に無い番号だと章名が出ない |
| `format` | `0` 固定 | 4択以外の形式を使うとUIが変わる |
| `timeLimit` | 30 推奨 | 他科目と体感を揃えるため |

## ID の付け方（重複を防ぐ）

分野ごとに番号帯を分けています。追加するときはその帯の末尾に続けてください。

| chapterId | 章 | ID帯 | 現在の最大 |
|---|---|---|---|
| 1 | 情報社会 | `j1xx`, `j5xx`, `j7xx`, `j9xx` | `j912` |
| 2 | デジタル化 | `j2xx`, `j5xx`, `j6xx`, `j7xx`, `j8xx`, `j9xx` | `j926` |
| 3 | プログラミング | `j3xx`, `j5xx`, `j6xx`, `j7xx`, `j8xx`, `j9xx` | `j956` |
| 4 | ネットワーク | `j4xx`, `j5xx`, `j7xx`, `j9xx` | `j952` |
| 5 | データ活用 | `j4xx`, `j5xx`, `j6xx`, `j7xx`, `j8xx`, `j9xx` | `j966` |

> 新規追加は **`j967` 以降**を使ってください（`j9xx` は分野をまたいで通し番号）。

> 帯が混ざっている箇所があるため、**追加前に必ず既存IDの一覧を出して**重複していないか確認してください。

```bash
grep -o '"j[0-9]*"' src/battle/data/pool.joho.generated.ts | sort | uniq -d
# ↑ 何も出力されなければ重複なし
```

## 追加後にかける機械検査

問題を足したら、下のスクリプトを走らせてください。ZIP作成時に実際に使ったものと同じ検査です。

`check.mjs` として保存し、`node check.mjs` で実行します。

```js
import { POOL } from './src/battle/data/pool.joho.generated.ts';

const ids = new Set();
let ng = 0;
POOL.forEach((r, i) => {
  const [id, ch, , , fmt, , label, opts, ans] = r;
  const err = [];
  if (ids.has(id)) err.push('ID重複');
  ids.add(id);
  if (!Array.isArray(opts) || opts.length !== 4) err.push('選択肢が4個でない');
  else if (new Set(opts).size !== 4) err.push('選択肢が重複');
  if (typeof ans !== 'number' || ans < 0 || ans > 3) err.push('answerIndexが範囲外');
  if (typeof label !== 'string' || label.length > 110) err.push('問題文が110字超');
  if (![1, 2, 3, 4, 5].includes(ch)) err.push('chapterIdが不正');
  if (fmt !== 0) err.push('formatが0でない');
  if (err.length) { ng++; console.log(`NG 行${i + 1} ${id}: ${err.join(' / ')}`); }
});
console.log(`総数 ${POOL.length} / NG ${ng}`);
```

> TypeScript を直接 import できない環境なら、`reference/joho-pool.json` を編集元にして
> JSON側で検査 → TSを再生成する流れが簡単です。

## 解説（explain）も一緒に足す

問題を1問足したら `explain.joho.generated.ts` にも同じIDで1行足します。

```ts
"j967": { why: "正解の解説", wrong: ["誤答0の理由", "", "誤答2の理由", "誤答3の理由"] },
```

- `wrong` は **4要素固定**。正解の位置は `""`、他3つは「なぜ誤りか」を1〜2文で。
- 「誤りの理由」は選択肢の言い換えではなく、**どの誤解でその選択肢を選んでしまうか**を書くと学習効果が高い
  （例：数値問題なら「8で割り忘れた値」「終値を含めなかった回数」のように、誤答に至る計算を明示する）。

## 章の問題数を必ず合わせる

問題を足したら、`chapters.joho.generated.ts` の `count` も更新します。

```ts
export const JOHO_CHAPTERS: readonly JohoChapter[] = [
  { id: 1, subject: "joho", name: "情報社会",     count: 16 },
  { id: 2, subject: "joho", name: "デジタル化",   count: 29 },
  { id: 3, subject: "joho", name: "プログラミング", count: 40 },  // ← 足した数だけ増やす
  { id: 4, subject: "joho", name: "ネットワーク", count: 10 },
  { id: 5, subject: "joho", name: "データ活用",   count: 11 },
];
```

そして **`POOL_COUNTS` の `joho:` の数値も同じだけ増やす**のを忘れないでください
（`既存ファイルの変更点.md` 変更1）。

```
count の合計 == POOL.length == POOL_COUNTS.joho
```

この3つが常に一致している状態を保ちます。

## 良い問題にするコツ（情報Ⅰ固有）

### プログラミング（chapterId 3）

DNCL（大学入試センターの共通テスト用プログラム表記）の仕様から外れると、
本番と違う知識を覚えてしまいます。特に間違えやすい点：

| 項目 | 正しい仕様 | よくある誤り |
|---|---|---|
| 論理演算 | `and` / `or` / `not`（英語） | 「かつ」「または」と書く |
| 剰余 | `％`（全角） | `%`（半角）や `mod` |
| 商 | `÷` | `//` |
| べき乗 | `**` | `^` |
| `乱数()` | **0以上1未満**の小数 | 「0以上1以下」と書く |
| サイコロ | `整数(乱数()*6)+1` | `整数(乱数()*7)` |
| 繰り返しの終値 | **終値を含む**（0から9まで＝10回） | 9回と数える |
| 配列の添字 | **0から** | 1から |
| コメント | `#` 以降 | `//` |

### 選択肢の作り方

- 誤答は「なんとなく違う」ではなく、**典型的な誤解1つずつに対応**させる。
  例：繰り返し回数の問題なら「終値を含めない誤り(9回)」「1つ多く数える誤り(11回)」を必ず入れる。
- 「すべて正しい」「どれも正しくない」といった選択肢は使わない。
- 長さを揃える。1つだけ極端に長いと、それが正解だと推測されてしまう。

### 難易度の目安

2025年共通テスト情報Ⅰ本試験の小問別正答率（平均 69.26/100）を基準にしています。

| 大問 | 配点 | 正答率 |
|---|---|---|
| 第1問（情報社会） | 20点 | 65.44% |
| 第2問（デジタル化） | 30点 | 76.11% |
| **第3問（プログラミング）** | **25点** | **64.73%** ← 最難 |
| 第4問（データ活用） | 25点 | 68.64% |

プログラミングを40問と最も厚くしているのは、この正答率の低さに対応するためです。
